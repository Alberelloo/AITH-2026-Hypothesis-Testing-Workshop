# Карта «ограничение → дизайн»

Артефакт встречи 5. Как пользоваться: найдите строку со своим ограничением или симптомом, возьмите дизайн, до запуска пройдите колонку «Что проверить», а перед докладом — «Ловушку». Строки 1, 3, 4, 6, 7 и 8 содержат числа кейса «Сеть магазинов» из `practice.ipynb` и `theory.ipynb`. Пустая строка 12 — для своих случаев; копируйте её.

| № | Ограничение / симптом | Дизайн | Что проверить | Ловушка |
| :---: | --- | --- | --- | --- |
| 1 | Воздействие назначается группе: магазину, городу, классу, складу. Наблюдений много, единиц рандомизации мало | **Кластерный A/B**: рандомизируем кластеры, анализируем одно число на кластер (или кластеризованные ошибки) | ICC и $DE = 1 + (m-1)\rho$ по истории; A/A на истории с тем же анализом ≈ 5% | t-тест по строкам. Кейс: ICC 0.94, 12 недель → DE 11.3, A/A срабатывает в 58% вместо 5% |
| 2 | Кластеров мало (10–40), они разного размера | Кластерный A/B со **стратификацией или парами**, рандомизационный тест вместо нормального | MDE с $t$-квантилями на $2(k-1)$ степеней свободы; поправка на разный размер (CV размеров); A/A на истории с тем же анализом — при $k < 30$ это главная проверка | Крупнейший кластер решает исход; асимптотическая ошибка при $k < 30$ занижена |
| 3 | Оффлайн-пилот: магазинов десятки, есть история продаж | **Пары + DiD**: пары по уровню и форме кривой до старта, монетка внутри пары, анализ изменений $\Delta_i$ по парам | Мощность **инъекцией эффекта** по истории; пары подбирать на одном отрезке истории, мощность считать на другом, плацебо — с переподбором пар для каждой фиктивной даты | Ждать мощности от недель: она покупается магазинами. Кейс: 40 → 80 магазинов даёт MDE 1.32% → 1.00%, 8 → 12 недель — только 1.45% → 1.32% |
| 4 | Список пилотных точек составил бизнес («сильные», «растущие» магазины) | **DiD с матчингом и поправкой на тренд**; вывод — оценка с допущением, не результат A/B; следующая волна — монетка внутри пар. Если есть год истории — годовая база (DDD) | **Плацебо по датам**: тот же расчёт (весь конвейер, включая подбор пар) на окнах до старта должен давать ≈ 0; сравнение трендов до старта; стресс-тест: сдвиг оценки при изломе тренда сравнить с запасом до порога решения; правило решения записать до просмотра оценки (порог, уровень интервала, допуск плацебо) | Узкий интервал ≠ отсутствие смещения; матчинг по уровню не лечит разницу в росте; плацебо ≈ 0 не доказывает отсутствие излома в окне пилота. Окно плацебо не должно пересекаться с неделями, по которым что-то подбирали: внутри окна отбора плацебо раздуто, внутри окна подбора пар — занижено. Кейс: наивный DiD +5.8%, плацебо +2.3%, пары +5.9%, с поправкой на тренд +3.6% при истине +3.53%; излом тренда сдвигает её на 0.9–1.9 п.п. при запасе до порога 0.9 п.п. |
| 5 | Изменение нельзя таргетировать на пользователя: ТВ, наружка, цены, офлайн-продажи; единица — регион | **Geo-эксперимент**: пары регионов, регрессия на историю (GBR/TBR), Trimmed Match | MDE по истории регионов; плацебо по датам; утечка через границы (люди ездят в соседний регион) | Без учёта истории MDE в десятки процентов; суммы по группам решают самые крупные регионы |
| 6 | Рандомизация невозможна: 1–2 тестовых региона или магазина, внедрение уже случилось | **Синтетический контроль**: неотрицательная смесь доноров повторяет кривую теста до старта | Качество подгонки до старта; плацебо по датам и по донорам (каждый донор в роли «теста»); тест внутри облака доноров по уровню **и динамике** | Смесь не выходит за выпуклую оболочку доноров. Кейс: пилот растёт быстрее всей сети → синтетика даёт +7.8%, плацебо +2.8…+4.0% |
| 7 | Общий ресурс: курьеры, водители, склад, рекламный бюджет. Тест забирает ресурс у контроля (нарушение SUTVA) | **Switchback**: рандомизация зона × окно времени | A/A по эпохам; длительность переноса (carryover) по истории переключений; баланс по часам и дням недели | A/B по пользователям видит эффект, которого нет: при дефиците курьеров +7.3 п.п. при истинном 0 |
| 8 | Switchback: эффект набирается не сразу, после переключения система «помнит» прошлый режим | **Окно около 3 длительностей переноса + burn-in** (первые $m$ часов окна в анализ не идут) | Смещение и разброс по сетке окон на симуляции или истории; A/A по эпохам ≈ 5% | Короткое окно без burn-in занижает эффект на $\tau m/(2w)$ (при $w \ge m$); t-тест по часам на A/A — 24–66%. Кейс: перенос 2 ч → минимум RMSE при 3 ч, с запасом 6 ч |
| 9 | Пользователи связаны сетью: друзья, чаты, общий аккаунт семьи | **Кластеры на графе** (рандомизация сообществ), ego-кластеры | Доля рёбер внутри кластера; тест на остаточную интерференцию (сравнение экспозиции соседей) | Мелкие кластеры плохо изолированы, крупные дают мало единиц: компромисс bias ↔ дисперсия |
| 10 | Двусторонний маркетплейс: изменение для продавцов влияет на покупателей и наоборот | **Двусторонняя рандомизация** или кластеры рынка (категория × город); switchback по рынку | Метрики обеих сторон; эффект на долю ресурса у контроля | Каннибализация: тест забирает спрос у контроля, а сумма по рынку не растёт |
| 11 | Эффект проявляется не сразу или затухает: привыкание, новизна, накопление запасов | **Длинный пилот** или holdout после раскатки; анализ по когортам старта | Динамика эффекта по неделям; сравнение первых и последних недель | Решение по первым неделям; перенос оценки пилота на всю сеть без перевзвешивания по форматам |
| 12 | _ваше ограничение_ | | | |

## Как выбрать строку

1. **Кому назначается воздействие?** Пользователю — обычный A/B (если нет строк 7, 9, 10). Группе — строка 1 или 2.
2. **Можно ли выбирать случайно?** Да — строки 1–3, 7–8. Нет, список уже есть — строки 4 и 6, а вывод формулируется как оценка с допущениями, не как результат A/B. Правило решения (порог, уровень интервала, допуск плацебо) запишите до того, как увидите оценку.
3. **Делят ли группы общий ресурс?** Да — строки 7–10. Обычный A/B даёт смещение, которое не уменьшается от роста выборки.
4. **Сколько независимых единиц на самом деле?** Посчитайте эффективное $n = n / DE$ и MDE инъекцией по истории до того, как обещать срок.
