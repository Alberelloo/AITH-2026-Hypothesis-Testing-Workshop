# Встреча 2. План теста

## О чём встреча

На встрече 1 мы решили, что новый чекаут стоит тестировать: решение по конверсии — против точки безубыточности 0.246 п.п. с α = 0.5, 105 тыс. пользователей (B — 21 тыс.), 14 дней. Теперь превращаем эти числа в план теста: что рандомизируем, что именно доказываем, какой эффект тест видит, честен ли критерий на наших данных, какие метрики за что отвечают, хватает ли 14 дней guardrail и как сделать тест короче. Выход встречи — дизайн-док, с ним идём на встречу 3 (запуск и доверие к данным).

Кейс — чекаут из `data/checkout_ab.csv`: конверсия ≈ 70%, 7.5 тыс. пользователей в день, сплит 80/20, предпериод 28 дней для CUPED.

## Ключевые концепции

- **Единица рандомизации и единица анализа** — пользователь против заказа или показа; если они различаются (средний чек, CTR), нужен дельта-метод или линеаризация; если рандомизировать можно только крупнее — встреча 5.
- **Вид теста** — superiority с границей 0, non-inferiority и equivalence с допуском Δ, решение против порога безубыточности θ_BE из встречи 1; MDE ≠ Δ ≠ θ_BE.
- **Одна формула для N и MDE** — сторонность и граница нулевой гипотезы как явные параметры. Тест встречи 1 видит 0.54 п.п. с мощностью 0.8; стандартный тест против нуля на тот же эффект — 47 дней вместо 14.
- **Цена решений дизайна** — относительный MDE против абсолютного (×2), сплит 80/20 против 50/50 (×1.56 по пользователям: 14 дней трафика против 9, но в целых неделях оба — 2 недели), односторонняя альтернатива (−21%); длительность — в целых неделях.
- **Решение против θ_BE** — α = 0.5 из финмодели значит «внедряем, если оценка выше BE»; против нуля это α ≈ 0.24. Симуляция: «внедряем» при эффекте 0 / θ_BE / MDE — 0.24 / 0.50 / 0.80; A/A на своих данных ≈ 0.05.
- **Критерий под тип метрики** — одна таблица «тип → критерий → ловушка»; любой критерий проверяется A/A-симуляцией на своих данных; «n > 30» для выручки не гарантия; значимый Манн–Уитни — не рост среднего.
- **χ² на согласие = SRM** — мост ко встрече 3.
- **Роли метрик и поправки** — качество данных → OEC → guardrail → диагностические; поправки по правилу запуска (Spotify): OEC без поправки, guardrail односторонне с мощностью 1 − β/(G+1), диагностические — по семейству. В кейсе β-поправка только у guardrail: мощность OEC 0.8 задана встречей 1, поэтому общий промах правила ≤ 0.3, и только если guardrail набрал 0.9 (на 14 днях с мощностью guardrail 0.58 — ≤ 0.62).
- **Мощность guardrail** — ошибки оплаты с допуском +0.2 п.п. хотят 262 тыс. пользователей (35 дней); на 14 днях мощность ≈ 0.58. Решение — правило эскалации: верхняя граница ≥ +0.2 п.п. → «не внедряем как есть», подтверждающий тест 50/50 на 0.9 — 168 тыс., 4 недели.
- **Ускорение** — N пропорционален дисперсии: стратификация (и почему стратифицированное сэмплирование без стратифицированного среднего даёт α ≈ 1%), CUPED (дисперсия × (1 − ρ²), несмещённость, CUPED ≈ регрессия; на ARPU кейса −37%, 28 → 18 дней), линеаризация (сама дисперсию не снижает), выбросы (свой порог в группах ломает тест, корректна винзоризация порогом предпериода).

## Вопросы для обсуждения

| Раздел | Вопрос |
| --- | --- |
| Единицы | Что не так с t-тестом по заказам для среднего чека? |
| Вид теста | «Guardrail: MDE = +0.2 п.п.» — что перепутано? |
| Размер выборки | «Хотим ловить +1%» — что уточнить до расчёта N? |
| Размер выборки | Почему тест встречи 1 втрое дешевле стандартного — не обман ли это? |
| Правило решения | Как часто правило внедряет нейтральное изменение и провал ли это? |
| Критерии | Выдержит ли t-тест Уэлча α = 5% на выручке при «n > 30»? |
| Критерии | Значимый Манн–Уитни — значит ли, что ARPU вырос? |
| Роли метрик | Почему у guardrail поправка на β, а не на α, и почему не α = 0.5? |
| Роли метрик | Мощность guardrail 0.58 — три варианта, что делать |
| Стратификация | Стратифицированные группы и обычный t-тест — что с α и мощностью? |
| CUPED | Может ли CUPED увеличить дисперсию? Можно ли взять ковариату за первые дни теста? |
| Выбросы | Свой порог 1% в каждой группе или общий порог — что ломается? |
| Дизайн-док | Почему правило решения пишем до старта? |
